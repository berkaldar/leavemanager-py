## Risks & open questions
- **A redirect proves nothing here** (the list opens after a save and after a silent loss).
  Every submission test asserts the response and `Db.requests` / `Db.next_id` (spec R-2).
  Recommendation: accept; a small local helper `post_request(client, **fields)` returns the
  response and the before/after state, used only inside this file.
- **Form markup is asserted by exact substrings** of the page (`<select name="employee_id">`,
  the five `<option value='n'>` lines, `<input type="date" name="start">`, …). Recommendation:
  accept; no snapshot of the whole page, so the title and navigation stay spec 0002's.
- **Test-only data:** the markup-in-name case sets `Db.employees[0]["name"]` directly; the
  autouse `seed()` resets it.
- **Error text:** only "HATA", "bakiye yetersiz" and HTTP 200 are asserted; the internal code and
  the phone extension are not (spec Constraints, B-10).
- **Screenshots (spec User experience):** VERIFY renders three states through `test_client`
  (empty form, error page, request list after a successful submit) and captures them headless,
  outside the repo, no server (B-9). Recommendation: accept.
- **Sensitive area** — VERIFY breaks each criterion once; no one-pass review.
