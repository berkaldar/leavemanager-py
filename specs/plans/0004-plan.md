## Risks & open questions
- **Spec ↔ shipped tests (R-10):** found at PLAN, resolved by spec revision 1 (two Supersedes,
  narrowed assertions). Recommendation: none further.
- **AC-7 "the demo password appears nowhere in the repository":** the tests need a password, so a
  fixed fake one (`test-only-password`) lives in `tests/conftest.py`. Recommendation: accept —
  the demo password the running app uses comes from the environment and is never committed;
  review and QA check with `git grep`.
- **Hash cost:** Werkzeug's default hash takes ~0.1 s. Recommendation: hash once per process
  (memoized) and sign the fixture in through the session; only the real login tests pay for
  verification.
- **Unknown URLs** (no endpoint) pass the guard and answer 404, so an anonymous visitor learns
  nothing but that a path does not exist. Recommendation: accept.
- **Debug mode stays** (`app.run(debug=True)`, B-9): the Werkzeug console is still reachable
  while the app is served that way. Recommendation: out of scope as the spec says; do B-9 next.
- **Residue:** the start-up test starts a short-lived subprocess. `check.conf` is unchanged, but
  I run the residue test for both profiles anyway.
- **Models:** BUILD is the most security-critical code in the project. Recommendation: you run
  `/model` and switch to Opus before BUILD; REVIEW and VERIFY run as Opus subagents as always.
- Environment: doctor `0 fail, 0 warn` — profiles fast and full runnable; no new prerequisite or
